# 商业模式验证

## 适用场景
- 新产品/新业务立项前的需求验证
- 增长停滞时对商业模式根本假设的复盘
- 融资路演前对核心假设的证据补强

## 方法
1. 假设清单拆解：把商业模式拆成可验证的原子假设——需求假设
   （目标客户真有此痛点）、付费假设（愿意为此付钱）、获客假设
   （能以可承受成本触达）、交付假设（能按承诺成本交付），
   每条假设写明「若证伪则模式不成立」的判定条件。
2. 风险排序：按「证伪代价 × 不确定性」给假设排序，优先验证
   最致命且最没把握的假设，不平均用力。
3. 最小实验设计：为每条假设设计最低成本实验——访谈（问过去行为
   不问未来意愿）、假门测试、预售/众筹、手工交付（ concierge MVP）、
   小流量投放；明确样本量、成功线、失败线与截止时间。
4. 实验执行与记录：实验过程数据全留痕，区分「用户说的」与
   「用户做的」，以付费、留存、转介绍等行为数据为准。
5. 真伪需求判别：汇总实验证据，给出每条假设的判定（验证/证伪/
   证据不足），证伪项提示转向或放弃的决策点，不替客户拍板。

## 输出契约
- 假设清单：每条 = 假设内容 + 证伪条件 + 风险等级。
- 实验设计卡：实验方法 + 样本量 + 成功/失败线 + 成本预算 + 截止时间。
- 验证报告：每条假设的判定 + 行为证据（带出处）+ 下一步建议。
- 继续投入还是转向的决策留给创始人；AI 只保证「用最小成本把问题问清楚」。
