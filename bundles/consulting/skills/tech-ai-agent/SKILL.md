# AI Agent 应用落地

## 适用场景
- 单轮问答已满足不了需求，要让 AI 自主完成多步骤任务
- 企业想试点 Agent（如自动调研/周报生成/跟单提醒）但缺方法
- Agent 演示效果好、生产环境不稳定，需要工程化改造
- 需要为 Agent 设定权限边界与验收标准

## 方法
1. 任务适配判断：Agent 适合「步骤多、需调用工具、中间结果
   影响后续动作」的任务；流程完全固定的优先 RPA/工作流，
   单步生成的优先普通 LLM 调用——不为炫技上 Agent。
2. 工作流编排：把任务拆为节点图（规划/检索/调用/校验/
   汇总），明确每个节点的输入输出与失败处理；关键节点
   设确定性校验（规则/格式检查），不把全部判断交给模型自由发挥。
3. 工具接入：工具清单逐个定义——功能描述、参数 schema、
   权限等级、幂等性；写操作（发消息/下单/改数据）默认
   需人工确认或限额围栏（C-R7）。
4. 评测集先行：上线前构建 30-100 条覆盖正常与边界 case 的
   评测集，跑通率与人工抽检合格率双达标方可上线；
   评测集随业务变化持续更新。
5. 可观测与兜底：全链路 trace 留痕（调了什么工具、
   中间推理摘要、耗时成本）；设最大步数/成本上限熔断，
   异常自动降级为人工工单。
6. 迭代节奏：以周为单位分析失败 case，区分「提示词问题/
   工具问题/任务定义问题」，对症下药而非笼统「换更强模型」。

## 输出契约
- 任务适配结论：为什么用/不用 Agent 的判断依据。
- 编排设计图：节点图 + 失败处理 + 确定性校验点。
- 评测报告：评测集规模、通过率、失败 case 分类归因。
- 工具权限审批表：写操作围栏与人工确认节点（C-R7）。
- 上线放行由业务 owner 依据评测数据决策；Agent 自主执行
  的边界（哪些必须转人工）须人类书面确认。
