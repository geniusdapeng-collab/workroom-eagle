# 用户需求洞察

## 适用场景
- 新品定义前需要系统理解目标用户的真实痛点
- 存量产品差评/投诉文本堆积，需结构化归因
- 客户已有访谈录音/问卷开放题，缺人力做编码分析

## 方法
1. 语料汇聚：电商评论、应用商店评论、社媒提及、客服工单、
   访谈逐字稿；统一清洗（去广告、去刷评嫌疑样本），记录语料规模与时间窗。
2. 合规前置：含用户昵称、手机号、订单号等 PII 的文本先脱敏再入库
   （C-R5）；外部采集仅用公开内容，注明平台与采集方式。
3. 语义聚类：对诉求语句做嵌入聚类，形成需求簇；每簇命名用「用户原话
   关键词」，禁止用咨询黑话命名，保证客户看得懂。
4. 三层归因：每簇标注层级——功能需求（要什么）/ 场景需求（什么时候要）/
   情感需求（怕什么、爽什么）；引用原声引文作证据，每簇 ≥5 条引文。
5. 量化排序：按提及频次×情感强度×付费意愿信号三轴给需求簇排序，
   区分「声量大但忍耐度高」与「声量小但致命」的需求。
6. 洞察输出：需求地图+Top 痛点深描+机会点假设；产品取舍与优先级
   决策必审（C-R2），AI 不替客户决定做什么。

## 输出契约
- 需求地图：聚类簇+频次+情感强度+原声引文（每簇 ≥5 条）。
- 语料说明：规模、来源、时间窗、清洗规则透明可查。
- PII 脱敏前置（C-R5），报告中不出现可识别个人身份的信息。
- 机会点仅为假设，优先级与资源投入必审（C-R2）。
