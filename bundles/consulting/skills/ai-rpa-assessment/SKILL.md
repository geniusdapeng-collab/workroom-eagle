# RPA机会评估

## 适用场景
- 财务/人事/供应链存在大量跨系统复制粘贴，想评估自动化
- 企业纠结选传统 RPA 还是 AI Agent，需要适用边界判断
- 已上 RPA 但机器人频繁「跑死」，需要稳定性整改
- 需要一份按 ROI 排序的自动化机会清单

## 方法
1. 操作盘点：通过访谈与屏幕录制收集重复操作，记录五要素——
   触发方式、操作步骤、涉及系统、频次、单次耗时；
   形成操作台账，条目须有实证而非员工自述估算。
2. 可行性分级：按四维打分——规则确定性、界面稳定性、
   异常占比、数据结构化程度；分为三级：
   - L1 直接 RPA（规则固定、界面稳定）；
   - L2 Agent 适用（需理解非结构化内容或动态判断）；
   - L3 暂不自动化（异常多或规则频繁变动）。
3. RPA vs Agent 边界：明确「界面操作自动化找 RPA，
   语义理解与生成找 Agent」；能用 API 打通的不走界面 RPA，
   避免脆弱脚本。
4. ROI 测算：收益 = 年节省工时 × 人力单价 + 差错损失下降；
   成本 = 许可/开发/运维 + 异常处理人工；只把回收期
   18 个月以内的列入实施清单。
5. 试点与推广：选 1-2 个 L1 场景 4-6 周上线试点，
   验证稳定率（目标 ≥95%）后再批量推广；建立机器人
   运行监控与异常工单机制。

## 输出契约
- 操作台账：五要素齐全，附录制/访谈依据。
- 机会分级清单：L1/L2/L3 分级 + 四维打分 + ROI 测算口径。
- 试点方案：场景、目标稳定率、验收标准与推广门槛。
- 涉及资金支付、对外发送的操作必须保留人工复核节点（C-R7）；
  自动化范围与上线节奏由业务负责人批准。
