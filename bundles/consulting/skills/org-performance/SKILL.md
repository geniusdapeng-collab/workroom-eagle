# 绩效体系设计

## 适用场景
- 绩效考核流于打分，不与目标联动
- 指标拍脑袋、权重随意，员工不认账
- 绩效结果应用单一，只与奖金挂钩

## 方法
1. 工具选型：按业务特性选 KPI（结果可量化）/ OKR（探索性强）/
   360（协作与价值观），允许组合使用但写明各工具适用岗位范围，
   避免全员一刀切。
2. 指标库建设：公司级指标从战略地图承接，
   部门指标用「价值树分解法」拆到可执行层，
   每个指标写明定义 / 计算公式 / 数据来源 / 考核周期，
   数据来源不可靠的指标一律不入库。
3. 目标值设定：用「历史基准 + 改善幅度 + 外部对标」三参照定目标，
   挑战值与保底值的达成逻辑写明，防止博弈性低报。
4. 强制分布设计：如采用，明确分布比例（如 2:7:1）、
   适用前提（部门人数 ≥ 10）与保护条款；
   写明强制分布的适用边界与副作用提示。
5. 校准会机制：部门初评 → 跨部门校准会（对比例证法：
   同一等级拿出事实对比）→ 管理层终审，
   提供校准会议程与举证模板。
6. 结果应用：绩效与薪酬 / 晋升 / 发展 / 改进计划（PIP）
   的联动规则；PIP 涉及劳动关系风险，规则文本须法务审（C-R7）。

## 输出契约
- 绩效制度：工具选型说明 + 指标库（带数据来源）+ 目标设定规则。
- 校准会模板与强制分布规则（含适用前提与保护条款）。
- 绩效结果应用方案涉及个人利益与潜在劳动关系争议，
  触发必审（C-R2/C-R7），附合规提示：落地前请执业律师审 PIP 条款。
- 个人绩效数据按 C-R5 脱敏前置，最小可见授权。
