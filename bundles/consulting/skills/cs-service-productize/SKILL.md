# 服务产品化

## 适用场景
- 同类项目重复交付 3 次以上后的标准化封装
- 获客前端需要「货架式」产品降低客户决策门槛
- 从卖时间转向卖产品的商业模式升级

## 方法
1. 产品候选筛选：从知识库筛「复用 ≥3 次、交付周期可预测、
   客户价值可量化」的方法论作为产品候选；
   强依赖个人临场发挥的部分标为「不可产品化段」，留在定制服务里。
2. 标准品定义五定：定场景（什么客户在什么时刻买）、
   定范围（做什么不做什么，写进一页纸）、定交付物（清单级）、
   定周期（含客户配合事项）、定价格（见第 4 步）；
   范围外事项统一走「变更单」流程。
3. 交付流水线：把产品拆为「自动化段（文档/数据生产线）+
   标准动作段（访谈/工作坊清单）+ 判断段（人类顾问）」，
   判断段占比写入成本模型；每交付一次记录工时与走样点。
4. 定价三锚：价值锚（客户可得收益的 10-20%）、
   成本锚（工时×目标时薪×1.5 风险系数）、
   市场锚（同类服务报价带）；三锚取交集，单一锚定不准。
5. 货架化表达：产品页一屏说清——你是什么处境 → 我们做什么 →
   你拿到什么 → 多少天/多少钱 → 谁用过（脱敏案例）；
   销售材料与交付契约用同一套范围描述，防口径漂移。
6. 产品治理：每季度复盘各产品的成交率、毛利、交付走样率；
   走样率 >30% 的产品回炉重定义，连续两季度零成交的下架。

## 输出契约
- 产品定义书：五定齐备 + 流水线分段 + 变更单规则。
- 定价测算：三锚对照表与最终建议价，标注假设。
- 产品经营看板：成交率/毛利/走样率的季度数据。
- 最终定价与个案折扣由人类决定；产品页对外发布前过脱敏与合规复核。
