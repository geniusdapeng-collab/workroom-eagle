# 组织架构设计

## 适用场景
- 战略转型后现有架构不支撑新业务
- 规模扩张导致汇报线混乱、决策缓慢
- 部门墙严重，跨部门协同成本高

## 方法
1. 战略对齐诊断：把三年规划的战略主题与关键战役逐条映射到
   「哪个组织单元承接」，无人承接的战役即架构缺口的证据。
2. 流程主线梳理：先画核心价值链流程（从获客到交付回款），
   按「流程决定架构」原则识别必须一体化的环节与可以切分的环节。
3. 架构模式选择：职能制 / 事业部制 / 矩阵制 / 平台型按
   「业务多样性 × 规模 × 协同需求」选择；
   矩阵制须写明双线汇报的裁决机制，否则不建议采用。
4. 部门与汇报线设计：输出组织图 + 部门职责卡
   （使命 / 核心职责 / 关键接口 / 衡量指标），
   职责重叠与三不管地带逐项清零。
5. 决策权限表（RACI + 授权清单）：按事项类型列明
   谁提议 / 谁审核 / 谁批准 / 谁知情，重点校验
   「审批层级 ≤ 3 层」与「一线授权额度」两项效率指标。
6. 过渡方案：新旧架构切换的过渡时间表、平移规则与
   人员安排原则；涉及管理层任免与汇报关系变化
   触发必审路由（C-R2）。

## 输出契约
- 架构方案：组织图 + 部门职责卡 + 决策权限表 + 过渡时间表。
- 设计逻辑说明：战略映射表与流程主线图作为依据附件。
- 涉及具体人选安排只给「岗位任职要求」，不点名评价个人（C-R2 必审）；
  员工个人信息按 C-R5 脱敏前置。
- 架构最终方案与高管任免交客户一把手与董事会裁定。
