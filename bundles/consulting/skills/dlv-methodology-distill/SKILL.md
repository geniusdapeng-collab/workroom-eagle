# 方法论提炼

## 适用场景
- 同一类问题做过 3 次以上、手感成熟后的方法论化
- 复盘产出的改进清单需要升级为通用框架
- 对外输出（课程、文章、产品）前的方法论打包

## 方法
1. 素材归集：汇集同类项目（≥3 个）的复盘纪要、交付物、关键决策点，
   列出每个项目「做了什么动作 → 得到什么结果」的动作-结果对。
2. 共性抽象：对动作-结果对做横向比较，提取「跨项目重复出现且
   与好结果相关」的动作序列，抽象为阶段-步骤结构；
   每个步骤写清输入、动作、输出、常见坑。
3. 边界定义：明确方法论的适用条件（行业/规模/阶段/前置资源）与
   失效情形；没有边界的方法论是口号，不予入库。
4. 命名与图示：起一个客户能记住的名字（动词+对象，如「渠道体检六步」），
   配一张一页图（流程图或矩阵）；名字先在小范围试讲验证记忆度。
5. 验证闭环：
   - 回测：用历史项目数据走一遍方法论，检验能否复现当时结论
   - 前瞻：在下一个适用项目完整套用，记录走样点
   - 迭代：每复用一次登记一次修订，版本号管理
6. 定级发布：草稿（1 次验证）→ 标准（3 次验证且无重大走样）→
   招牌（≥5 次验证且可对外讲授）；级别写入知识库资产页。

## 输出契约
- 方法论文档：阶段-步骤结构 + 每步输入/动作/输出/常见坑 + 适用边界。
- 验证记录：回测与前瞻验证的过程与差异，版本修订历史。
- 一页图 + 命名，供提案与汇报直接引用。
- 方法论级别（草稿/标准/招牌）由人类评定；对外发布前必须脱敏复核。
