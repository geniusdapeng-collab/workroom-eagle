# 系统选型辅导

## 适用场景
- 企业要上 ERP/CRM/MES/HR 等系统，面对众多厂商无从比较
- 厂商方案天花乱坠，需要第三方视角拆解真实能力与报价水分
- 已有供应商入围，需要设计 POC 验证真实适配度
- 历史上吃过「选型失误」的亏，需要流程化、可留痕的决策过程

## 方法
1. 利益中立声明：本技能不与任何软件厂商、实施商存在佣金、返点或
   股权关联；若服务方存在关联，必须在选型启动前书面披露并回避。
2. 需求矩阵：把需求分为「必备 / 重要 / 加分」三级，每条需求附
   业务场景描述与验收标准；权重由业务部门打分而非 IT 单方定，
   防止选型变成技术参数的军备竞赛。
3. 供应商短名单：按行业案例、产品匹配度、实施能力、持续经营风险
   四个维度初筛 3-5 家；收集材料须交叉验证（客户背调不少于 2 家
   同行业客户，且由企业方亲自访谈）。
4. POC 验证：选取 2-3 个真实业务场景（用企业真实数据脱敏后测试，
   C-R9），设定量化通过标准；POC 结果当场记录、双方签字，
   不允许厂商用演示环境样板数据糊弄。
5. 商务与风险评估：拆解报价结构（许可/实施/年维/二开），
   核算五年 TCO；评估厂商锁定风险与退出条款。
6. 决策留痕：输出加权评分表与决策会议纪要，落选原因同样记录，
   供未来复盘。

## 输出契约
- 需求矩阵：分级需求清单 + 权重表 + 验收标准，业务部门签字确认。
- 短名单报告：每家厂商四维评分 + 客户背调纪要（注明访谈对象）。
- POC 报告：场景-通过标准-实测结果对照表，附原始记录。
- 最终推荐须给出 2 个以上选项与各自风险；签约与否、选谁，
  必须由企业决策层决定，AI 不推荐单一「标准答案」。
- 全文件头标注利益中立声明。
