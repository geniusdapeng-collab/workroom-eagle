# 数据合规

## 适用场景
- App/小程序上线前的个人信息处理合规自查
- 数据出境、向第三方共享数据前的合规评估
- 监管通报或用户投诉后的整改响应

## 方法
1. 处理活动盘点：梳理数据流向图——收集哪些字段、从谁收集、存于何处、
   共享给谁、保存多久、是否出境，形成个人信息处理活动清单（RoPA 雏形）。
2. 合法性基础核查：逐项核对处理活动的合法性基础（同意/合同必需/法定义务），
   敏感个人信息（生物识别、医疗健康、金融账户、未成年人）单独标记，
   核查是否满足单独同意与影响评估要求。
3. 用户权利响应检查：检查查阅、复制、更正、删除、撤回同意、注销账号
   六类权利的入口与响应时限是否可落地，隐私政策文本与实际处理是否一致。
4. 差距分级整改：按监管处罚风险分高/中/低三级，高级项（超范围收集、
   强制授权、SDK 未披露、出境未评估）给出立即停止+整改的止损建议。
5. 涉 PII 处理自约束：本系统自身处理客户提供的个人数据时执行脱敏与
   最小必要原则，原始 PII 不入档案（C-R5/C-R9）。

## 输出契约
- 个人信息处理活动清单：字段、来源、目的、共享方、保存期限、出境情况逐条列明。
- 合规差距清单：每项 = 问题描述 + 对应法规条款 + 等级 + 整改建议。
- 合规提示段落必备：本报告不构成法律意见，重大数据处理安排须经执业律师/
  数据合规专家复核（C-R7）。
- 是否出境、是否共享等商业决策留给客户；AI 只列各选项的合规要件。
