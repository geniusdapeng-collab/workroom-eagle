# PPT故事线

## 适用场景
- 项目立项会、诊断汇报、方案评审的演示材料
- 高管/董事会场景的精简汇报页
- 把长报告改写为可讲的演示版本

## 方法
1. 故事线先行：先在纸上排出 1 页目录 + N 页标题（每页一个完整句子），
   通读标题能独立成文（「标题流测试」）才进入排版；标题写不出结论的页删除或合并。
2. 三段式叙事骨架：为什么（痛点与代价）→ 是什么（结论与方案）→
   怎么做（路径与保障）；高管版压缩「怎么做」，执行版压缩「为什么」。
3. 标题即结论：每页标题 = 观点句（含数字与方向），
   禁用「市场分析」「现状介绍」类名词标题；副标题放支撑逻辑。
4. 图表叙事：一页一图一信息，图上直接标注「所以呢」
   （圈出拐点、写上归因短句），不让读者自己找重点；
   图表编号与报告证据索引一致，可被追问下钻。
5. 页面密度控制：每页正文 ≤ 40 字 + 1 图；细节放附录，
   主讲页只留结论与关键证据；全篇页数 ≈ 汇报分钟数 × 0.7。
6. 预演校验：模拟三个最尖锐提问，检查答案分别落在哪一页，
   答不出的问题补页或备案口头回应。

## 输出契约
- 故事线大纲：页标题序列（每页一句结论）+ 各页证据索引，先于设计稿交付。
- 每个图表标注数据来源与口径，与报告底稿一致可回查。
- 附录承载细节，正文不得堆数据；涉敏页面的展示范围由人类决定。
- 现场讲法与取舍（哪页可跳过、哪页必讲）由人类顾问最终把握。
