# 技术成熟度评估

## 适用场景
- 客户考虑引入某项新技术（AI/区块链/新工艺）前的可行性评估
- 供应商宣称的技术能力需要独立核查
- 研发自研 vs 外采 vs 观望的路线决策支持

## 方法
1. 技术解构：把技术拆为底层原理层、工程实现层、应用集成层，
   分别评估成熟度，避免用一个标签概括整体。
2. 曲线定位：对照 Gartner Hype Cycle（最新版）定位技术阶段；
   国内技术同步对照信通院、中国信通院白皮书等本土权威报告。
3. 案例核查：检索真实落地案例，区分「POC 演示 / 小范围试点 /
   规模化商用」三档；优先采信有量化效果的商用案例，记录客户名与效果数据。
4. 关键指标对标：提炼该技术落地的关键指标（精度、时延、成本、
   稳定性），将供应商宣称值与第三方实测/论文基准对比，标注差异。
5. 约束条件清单：列出技术落地的前置条件（数据量、算力、人才、
   合规资质），逐条比对客户现状，输出就绪/缺口对照表。
6. 路线建议：输出「现在引入 / 试点先行 / 持续观望」初判及触发条件；
   技术选型与投资结论必审（C-R2）。

## 输出契约
- 评估报告：分层成熟度+曲线定位+案例三档统计+指标对标表。
- 每个案例标注来源与商用档位；宣称数据与实测数据分栏呈现。
- 就绪/缺口对照表客观呈现，引入决策必审（C-R2）。
- 注明评估时点与信息截止日，技术快速演进领域 3 个月内有效。
