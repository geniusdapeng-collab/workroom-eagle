# 六西格玛改善

## 适用场景
- 质量问题反复，原因不明、久治不愈
- 关键质量特性（CTQ）波动大，客户投诉集中
- 已有改善文化，需数据驱动的系统攻关

## 方法
1. Define 定义：用 VOC/CTQ 树把客户抱怨翻译为可测量的
   质量特性，立项书含问题陈述（基线数据）/ 目标（如缺陷率
   从 X ppm 降至 Y）/ 团队 / 收益测算。
2. Measure 测量：先做 MSA 测量系统分析（GR&R ≤ 10% 合格，
   10-30% 有条件接受），测量系统不过关不采数据；
   采集过程数据计算基线西格玛水平与 Cp/Cpk。
3. Analyze 分析：鱼骨图 + 5Why 穷举潜在因子 →
   C&E 矩阵筛选 → 假设检验（t 检验 / 方差分析 / 回归）
   验证关键因子，p 值与置信区间写明，区分相关与因果。
4. Improve 改进：用 DOE 试验设计优化关键因子参数，
   输出最优参数窗口；改进方案做 FMEA 风险评估后试行。
5. Control 控制：SPC 控制图（Xbar-R / P 图按数据类型选）上线，
   控制计划（反应计划 / 检查频次 / 责任人）+ 标准修订，
   30/60/90 天稳定性验证。
6. 收益核算：财务收益按「不良成本下降 - 投入」核算，
   由客户财务部门复核确认，不自行宣称。

## 输出契约
- DMAIC 项目报告：五阶段证据链完整——立项书 / MSA 结论 /
  假设检验结果（带统计量）/ DOE 结论 / 控制计划。
- 所有统计结论注明样本量、置信度与工具版本。
- 收益数字经客户财务复核后方可写入交付物。
- 涉及岗位技能要求变化与人员调整的内容触发必审（C-R2）。
