# 项目管理PMO

## 适用场景
- 项目多而乱，延期成常态，没人说得清全貌
- 资源被多头抢占，关键项目反而缺人
- 项目经理各自为战，缺统一方法与复盘

## 方法
1. 项目盘点与分级：全量项目清单化，按
   「战略关联度 × 投资规模 × 风险」分 A/B/C 三级，
   分级决定治理强度（A 级月度里程碑评审，C 级备案制）。
2. 立项闸门：立项书标准化——商业论证 / 目标与范围 /
   里程碑 / 预算 / 风险；A 级项目立项须过投资委员会，
   未立项不得占用资源。
3. 里程碑治理：统一里程碑定义（可验证交付物 + 验收人），
   里程碑评审会按「绿黄红」三色定状态，
   黄红项目必须提交纠偏计划与资源请求。
4. 资源冲突仲裁：建立资源池视图（关键人员负载率），
   冲突按「项目优先级 > 里程碑紧迫度」仲裁，
   仲裁规则由高管背书，PMO 只执行不擅自裁定（C-R2）。
5. 项目看板：组合层看板（全部项目状态 / 预算执行 /
   里程碑达成率）+ 单项目周报模板（进展 / 风险 / 求助），
   风险升级机制写明（红项 48 小时内到高管）。
6. 复盘与资产化：结项复盘模板（目标达成 / 偏差归因 /
   经验教训），经验入库供后续项目调用；
   项目经理能力分级与认证路径设计。

## 输出契约
- PMO 机制文件：项目分级标准 + 立项与里程碑模板
  + 资源仲裁规则 + 组合看板与周报模板。
- 项目状态数据取自系统或项目经理确认，挂回执。
- 资源仲裁涉及人员调配的决策交客户管理层（C-R2 必审）。
- 复盘报告的偏差归因聚焦流程与决策，不作个人定性评价。
