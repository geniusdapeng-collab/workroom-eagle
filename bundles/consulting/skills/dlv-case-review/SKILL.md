# 项目复盘

## 适用场景
- 项目结项或关键里程碑后的团队复盘
- 交付物被客户否决/重大返工后的事故复盘
- 续约/丢单后的经营复盘

## 方法
1. 事实还原：对照计划与时间线重建「原计划 → 实际发生 → 偏差」，
   只放可查证事实（邮件、纪要、数据），不许评价先行；
   参会人先各自独立写时间线再合并，避免互相锚定。
2. 归因分析：对每个偏差问三层为什么，区分三类原因——
   判断失误（信息足够但结论错）、信息缺口（该采集未采集）、
   执行走样（方案对但动作变形）；禁止归因于「客户不配合」这类不可操作项。
3. 双清单提炼：
   - 保持清单：哪些动作被验证有效、下次继续
   - 改进清单：每条改进必须写成「下次遇到 X 情境时，做 Y 动作」
     的可触发格式，不写「加强沟通」类口号
4. 归因校验：关键归因对照红队质检记录与客户反馈交叉验证；
   单方视角的归因标注置信度。
5. 固化入库：改进清单逐项决定去向——更新方法论 / 改模板 /
   进检查清单 / 仅个人备忘；30 天内完成固化动作并销项。
6. 复盘纪律：对事不对人，数据先于记忆，客户反馈权重高于内部感觉。

## 输出契约
- 复盘纪要：事实时间线 + 偏差归因表（含三层为什么）+ 双清单。
- 固化销项表：每条改进的去向、责任人、完成期限。
- 归因必须挂证据；争议性归因保留双方表述并标注置信度。
- 涉及个人责任的表述由人类顾问把关，复盘结论不直接用于绩效评价。
