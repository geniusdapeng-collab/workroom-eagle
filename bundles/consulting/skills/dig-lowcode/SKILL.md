# 低代码应用建设

## 适用场景
- IT 排期积压，业务部门想自建轻应用（审批/台账/巡检）
- 企业已引入低代码平台但野蛮生长，应用没人管、数据乱流
- 需要界定「什么可以低代码做、什么必须正规开发」
- 希望建立公民开发者（citizen developer）体系

## 方法
1. 机会识别：从业务痛点中筛选低代码适配场景，标准是——
   流程相对标准、用户量有限、数据敏感度低、生命周期
   3 个月-3 年；核心交易系统、财务核算、涉大量个人信息的
   场景明确划入禁区（C-R9）。
2. 平台选型与分层：评估平台的数据模型能力、集成接口、
   权限体系与导出能力；选型保持利益中立——不与任何平台
   存在佣金关联，如有披露并回避（利益中立声明）。
3. 治理框架：发布低代码管理办法——应用登记制（谁建的、
   干什么、数据存哪）、分级审批（按数据敏感度）、
   季度盘点（僵尸应用下线）；连接核心系统数据须经 IT 审批。
4. 公民开发者培养：每个部门培养 1-2 名种子用户，
   提供模板库与培训认证；建立「业务提需求、种子搭建、
   IT 审架构」的协作流。
5. 生命周期管理：应用上线前安全检查（权限/数据外发），
   使用中监控用量，超阈值（用户量/数据量/关键性上升）
   触发「转正规开发」评估；下线时数据归档不留孤儿数据。

## 输出契约
- 机会清单：适配/禁区场景分类 + 判定依据。
- 低代码管理办法：登记、分级审批、盘点与退出条款（C-R9）。
- 公民开发者体系：角色、认证标准与协作流程。
- 应用是否接入核心系统数据由 IT 与合规共同审批；
  AI 提供评估框架，不作放行裁决。
