# 咨询报告线程执行合同

本合同面向鹰眼安装版维护者。普通任务入口中的公开研究报告，经咨询行业执行桥收集政府官网正文、冻结可追溯摘录，交由现有六员工流程形成内部报告待审稿。它解决普通任务此前进入通用 `archive.read`、却没有档案连接器而停在“未核实”的链路缺口。文件、状态与事件回执必须实际存在；任务完成不表示人类顾问已经批准内容。

## 入口和场景

1. 成员提交“做一个温州地区制造业的分析报告”等公开议题。请求有稳定的服务端派单 `requestId`，当前活动行业包为 consulting，任务模式为 quest；线程可以先进入 queued，随后由既有线程调度器调用行业执行桥。旧的未绑定线程不会按标题自动改类，agent 模式仍走逐步确认路径。
2. 顾问在资料采集或模型步骤中选择转人工。控制事件和线程 paused 投影在同一事务落库，后续自动调用停止；已经在途的原调用只结算原结果。整个原执行退出并写入 `execution.settled` 前，恢复按钮不可用。可恢复后提交 resume 仅把原线程置为 queued，等待调度器继续，不构造新目标或新请求。
3. 成员停止一个线程，或回来查看已生成报告。停止保留已冻结正文、草稿、费用与历史；已停止任务不能恢复。重复打开、读取报告、重复幂等控制请求和重复执行已完成线程均不再请求模型或搜索。

公开报告入口不读取任意本地路径或私人客户附件，不执行外发、客户通知、顾问访谈、谈判、资金、账务或任意工具调用。带私人资料、外发要求或凭据的议题被拒绝或转交人工处理。

## 来源和模型输入

每任务最多发起一次搜索并选择最多三份可读来源。查询保留明确指定的年份；没有年份时补实际当前年，冻结后始终复用原查询。URL 仅允许无凭据、无片段、默认 HTTPS 端口的 `gov.cn` 域名，排除令牌参数、本机地址和二进制文档。检索议题在发送前检查凭据及个人信息；来源正文还检查请求地区与行业词，官网域名本身不能证明内容适用。

搜索 JSON、每份供应商返回的完整 Markdown 正文及选择清单分别写入本机不可变文件，保留供应商 reservation、采集时间、完整字节数和 SHA256。发布日期仅取正文或搜索结果可解析值；没有值则明确保持未知，不把采集时间冒充发布日期。

模型使用总计不超过 4000 UTF-8 字节的来源结构，通常为每份正文中最多三段按议题、数字、期间和风险词选取的句子。每段披露完整原文中的 UTF-8 左闭右开字节范围和摘录摘要。含个人信息的候选整段排除；不能把脱敏后变化的文本称为逐字原文。完整返回正文仍保留，不能据此声称模型读完了整篇网页。词项检查和官方来源均不代替专业适用性审阅。

规划、六个员工步骤、搜索和抓取使用同一执行上下文。身份包含租户、工作区与原派单请求；没有派单请求的已绑定兼容路径才使用线程身份。上下文对确切输入持久保留 pending、settled 或 unknown 记录；已结算的同一输入复用原答案，pending/unknown 不自动重购。显式评测总预算文件仍优先覆盖任务级预算，执行桥不重置预算或更换模型。

六员工顺序与原工作流一致：诊断分析师开头，中间三名不同专业员工由模型选择，报告编撰官第五步、独立质检官第六步。岗位技能、真实安装状态、围栏、原文引用、全前序产物回读与确定算术矛盾校验均继续生效。报告汇编只拼接六份已校验草稿及真实来源目录，不购买额外的“汇总答案”。

## 状态、并发与恢复

线程自己的事件流保存 `eagle.consulting-task/v1` 状态，包含原目标摘要、requestId、actorId、父流程、来源检查点、进度、不可变报告文件、控制状态、当前 operation 和 execution claim。事件和线程投影使用同一 app 事务、工作区/租户上下文与任务 advisory lock；事件经安全网关的特权追加函数落库，app 角色不能直接 INSERT 事件表。

`execute` 先在同一锁下原子认领一个执行 ID。别的服务实例或进程再次进入，只回读当前状态；没有租约猜测、自动回收认领或并行购买调用。每次搜索、抓取、规划与员工推进还记录 operation；原结果落盘后清理 operation，整个执行退出后才清理 execution。转人工和停止始终可入账，但原 execution/operation 未结算时不能恢复。

父咨询流程的每次推进、重验和暂停/恢复都核对父任务控制及内部执行 ID。公开 `consulting.advance` 等接口不能抢占已绑定线程的执行，转人工或取消时先返回对应控制错误。旧的无父线程档案评测流程保持原合同。

行业执行桥先读取线程原有绑定。已经绑定的咨询线程，不因活动行业包切换而落回通用工具流程；执行入口及每一次新的来源、规划或员工推进前复核咨询包仍然有效。失效或变更时只保留原在途结果与回执，后续操作返回 `BUNDLE_NOT_READY`，不更换执行来源或购买下一次调用。已完成的历史报告仍能按原 scope 回读。未绑定且当前非咨询行业的线程继续由其原有执行器负责。

如果服务进程在执行认领结算前崩溃，持久认领保持待核验。产品当前不会凭超时推断原调用没发生，也没有自动修复未知认领的入口；维护者需要核对原模型操作缓存、预算、事件与文件后处理。不能通过新的幂等键、强行 resume 或删除账本重新购买答案。该保守失败路径不宣称已经验证任意宕机场景的自动恢复。

## 受控 API

三个任务接口均从实时成员权威上下文取 scope，输入 schema 为 strict；调用方不能提交 tenantId、workspaceId、文件路径、结果正文或完成状态。

| 接口 | 输入 | 结果与错误边界 |
| --- | --- | --- |
| `consulting.taskView` | `{threadId}` | 状态 queued/collecting_sources/planning/working/draft_ready/blocked/human_required/cancelled、六步进度、来源目录、报告摘要、真实回执及动作可用性。已存在报告时先回读完整文件并验散列。 |
| `consulting.taskReport` | `{threadId}` | 从同 scope 的任务状态选择服务端文件，返回完整 Markdown、字节数、SHA256、报告事件回执和 `humanReviewRequired:true`。无真实文件及回执则 `REPORT_NOT_READY`，篡改则 `PUBLIC_SOURCE_HASH_MISMATCH`。 |
| `consulting.taskAction` | `{threadId,action:resume\|handoff\|cancel,idempotencyKey,reason?}` | 必须具备实时 `task.dispatch` 权限。动作事件与线程投影同 COMMIT；返回独立 `actionReceipt`。同键同动作复用原回执；同键不同动作/原因/操作者返回 `IDEMPOTENCY_CONFLICT`。 |

跨真实工作区以及伪租户配原工作区的 service 调用均无任务、报告或动作结果。成员 middleware 每次实际回查 members→workspaces→tenants 的成员 ID、工作区、租户、状态与当前角色，不能由陈旧 owner claim 保留写权。既有事件表底层 RLS 按 workspace 过滤；新 service 同时加 tenant 与 workspace WHERE，这不是把底层策略描述为独立的双字段 RLS。

## 验证边界

本模块的免费测试使用隔离本机 PostgreSQL、真实 app 角色、真实网关追加函数、真实 Task/Workflow stores、完整本地文件与真实 tRPC middleware；只有模型及网页返回值是明确标注的夹具。覆盖报告/hash、跨 scope、角色实时收紧、任意 path 拒绝、转人工/恢复/停止、在途并发、原始步骤入口、技能卸载、围栏、未知调用、事务回滚与丢失 COMMIT 确认。夹具断言通过不代表真实公开搜索可用、真实模型内容正确或原生客户端体验已通过。

新增真实环境验收需单独绑定本次源文件、安装包和模型预算，保留原失败与旧评测证据。先前 40 次模型调用以及 35 件产物属于旧版本、旧入口评测；不能将它们改称为当前原生任务桥的实测结果。专业内容、人类顾问审批、真实客户经营效果与统计自主交付率仍需分别举证。
