# 鹰眼企业经营工作台与常驻 BOT

## 用户流程

从已装配咨询行业包的鹰眼工作区打开「经营工作台」。主管查看晨报、周月复盘、行动台账和 BOT 的运行记录。一线使用同一个 Web 地址，手机端按窄屏布局显示今日待办、跟进录入和结果回执。

1. 所有者通过现有成员权限流程向一线授予 `consulting.business.read`。工作区实际角色和显式拒绝项在服务端实时校验。
2. 先用「记一条跟进」录入商机、发生日期、事实与下一步。主管可以按公开表头约定预览并确认授权导出的 CSV。
3. 所有者在「BOT」签发限次数、到期时间和单次时限的内部经营分析委托。可以手动提交一次，或者启用北京时间的每日计划。
4. BOT 独立于网页和 API 进程工作。重新打开晨报或原任务可回读同一份快照、来源事实和回执。
5. 主管指定承接人、期限及验收条件。负责人提供同商机或同客户的新事实作为执行证据，由另一位具备权限的主管复核。动作已执行和结果已核验分别显示。

## 数据来源与口径

CSV 首行使用经营事实字段名，例如 `kind,occurredOn,accountRef,dealRef,sourceKind,sourceRef,note`。工作台会给出不同事实种类的字段要求。相同事实的修订应引用 `supersedesFactId`，已公布的快照可以按原观察时点回读。

| 视图 | 口径 |
| --- | --- |
| 增长 | 固定周期内的人民币签约额及新老客、历史未知分组 |
| 漏损 | 已记录应收与支付的逾期敞口、交付成本异常和逾期承诺 |
| 竞争 | 有证据的赢输反馈及覆盖率 |
| 渠道 | 比较两个相邻的成熟入组期，各 30 个自然日。按首个有效且可归因的触点分组，只统计入组日至第 30 天结束的推进和成交。两期各满 10 条且推进率下降至少 20 个百分点时提示复核。未知来源与未成熟样本单列 |

首期每个工作区是一个经营单元。分析使用已确认的记录，金额按人民币分保存。原始数据留在当前企业工作区的数据库。只有确切范围的回执和引用进入任务事件。工作台使用来源标签和覆盖提示解释缺口。正式客户的 CRM、财务系统和经营动作继续由各自授权入口处理。

## 云端运行

先用鹰眼已验证的部署流程安装依赖和迁移数据库。使用同源 HTTPS 提供构建后的 `apps/web/dist`，并将 `/trpc`、`/health` 和需要的 `/api` 转发给鹰眼 API。应用已有正式账号和授权链。工作区需要启用可信的咨询行业包。

在同一部署版本中运行独立 Worker。它使用现有应用数据库角色，一个进程绑定一个工作区。将数据库连接注入受信任的进程环境。

| 环境变量 | 用途 |
| --- | --- |
| `DATABASE_APP_URL` | 已迁移数据库的应用角色连接 |
| `WORKLOOM_BOT_TENANT_ID` | 被允许的企业租户 ID |
| `WORKLOOM_BOT_WORKSPACE_ID` | 被允许的工作区 ID |
| `WORKLOOM_BOT_POLL_MS` | 可选轮询间隔，默认 5000 毫秒 |

```sh
node --import tsx apps/server/src/industry/operating-bot/worker.ts
```

用进程管理器维持常驻。仓内 [systemd 单元](../ops/eagle-operating-bot.service) 可作为服务配置来源，部署时按实际 Node 路径、安装目录和受保护的环境文件调整。验收时看工作台的在线状态和最后成功调度时间。心跳和任务进展来自数据库，网页关闭后仍可运行。

## 接口与状态

`business.*` 沿用鹰眼原有 tRPC 授权和回执，不增加独立登录入口。能力目录和当前工位状态可从 `business.botStatus` 回读。通过 `grantMandate`、`submitTask`、`taskView` 和 `taskEvents` 写入委托、提交任务和回放历史。提交使用稳定幂等键，改参数复用原键会冲突。所有者可 `revokeMandate`，获准的管理者可 `cancelTask`。

BOT 当前能力是「读经营记录并生成内部简报」。其行为受生效行业包、实时权限、作用域、围栏、委托有效期和运行配额约束。数据库持久化每日触发点、队列、执行租约、尝试、产物和追加事件。已受理的任务先回读原编号。只有在准确的快照、事件和回执写入后，才显示成功。高风险和客户外发走企业原有人工流程。

## 验收与停用

- 授权后录入可核对的试点数据。关掉浏览器，在到点后从另一浏览器打开原晨报，确认任务、快照和引用能一致回读。
- 中途重启 Worker，核对原任务 ID、重领尝试、唯一产物和事件游标。分别测试重复提交、工作区之间的隔离、委托过期、临时数据库故障和取消。
- 停用时先撤销工作区的委托，复查原任务状态，再停 Worker。Web 仍可回读历史简报与已经分派的内部任务。历史表和证据可保留，按实际上线前快照和已验证迁移管理。
