# 鹰眼正式本机安装与验收

读者是客户装机人员和维护鹰眼客户端的工程师。正式安装直接进入当前电脑负责人的真实工作区；模型调用失败或凭据缺失会显示错误，不会自动生成模拟任务、模拟客户或模拟回执。

## 首次启动会安装什么

首次启动创建独立 PostgreSQL 实例，随机生成数据库三角色凭据和会话签名密钥，执行迁移，再运行 `scripts/seed-production.ts`。正式工作区是 `eagle-production`，本机负责人编号是 `OWNER`。这是一份受当前操作系统账户控制的正式成员身份，不是游客、共享演示账号或固定密码后门。公开 HTTP 接口不能只凭工作区和编号获得该身份。

初始化只写组织和产品元数据：正式工作区、本机负责人、数字员工岗位、行业技能、基线围栏和行业安装台账。客户档案列表、经营指标、任务、审批、夜班回执、客户会话及通知均为空。夜班自治默认不启用；外部消息通道默认禁用。重复安装不会覆盖已有客户档案，也不会把旧数据直接清空。

`pnpm db:seed` 与两套 setup 入口使用正式初始化。隔离回归测试需要示例数据时，必须显式执行 `pnpm db:seed:demo`；演示身份还需非生产环境及 `WORKLOOM_ALLOW_DEMO_AUTH=1`，而且仅能访问标记为示例的工作区。`NODE_ENV=production` 永远拒绝游客与演示身份入口。

## 模型与凭据

出厂无秘密配置是 `LLM_PROVIDER=deepseek`、`LLM_BASE_URL=https://api.deepseek.com`、`LLM_MODEL=deepseek-flash`。`deepseek-flash` 是供应商模型别名，其当前映射和实际返回模型必须以供应商文档与真实调用回执核对，不能把名称当作不可变快照。

模型密钥不编进源码、公版应用资源、Git、文档或配置模板。客户机器使用 Electron 的系统凭据加密能力，将密文保存到应用支持目录下的 `deepseek-key.enc`。启动后仅在主进程内解密，并通过子进程环境交给本地服务；网页与 MCP 都拿不到模型密钥。系统凭据服务不可用时拒绝保存明文。相关系统行为见 [Electron safeStorage 文档](https://www.electronjs.org/docs/latest/api/safe-storage)。

装机工具可以启动应用可执行文件并添加 `--import-model-key`，通过标准输入传入密钥后关闭输入流。密钥不能放在命令行参数、shell 历史或临时文本文件中。导入和正式启动必须使用同一个应用身份以及同一个支持目录；验收时通过 `WORKLOOM_SUPPORT_DIR` 显式选择独立目录。安装器导入后应用退出，再正常启动即可。

## 正式成员会话与本机 Agent

首页分别显示安装身份、客户资料、模型配置及经营门禁。新装应显示“正式安装、客户名单尚未接入”；配置过真实模型但没有向导连接测试记录时，仍如实显示该缺项，不改称模拟模型，也不伪造激活凭据。“可复核草稿”只统计已接受、已写盘且有真实同步回执的咨询分析产物；欢迎、安装及配置事件不算业务成果。

生产落地向导使用只读的当前模型配置。显式点击“验证当前模型（真实调用）”后，服务端才以当前受保护密钥执行有预算上限的真实请求，并在成功后记录当前配置的验证事实；首次请求会产生模型费用，不会自动把经营主体或其他门禁置绿。验证请求按真实租户与工作区持久化同一标识，失败、结果未知、刷新页面或成功后状态回读失败均继续查询原请求，不因重试自动产生新调用。本机存储不可用或请求记录损坏时在调用前停止。只有服务端明确返回当前配置已变化，页面才提供带新费用说明的显式重新验证按钮。生产网页拒绝保存明文模型密钥，变更密钥仍走上述安全导入。

桌面主进程每次启动产生随机安装会话秘密，只在本进程与本地服务进程环境中流转。主窗口通过用途固定的 preload IPC 请求正式会话；主进程会校验发送者、顶层窗口和完整来源。HTTP 的 `/api/desktop/session` 必须携带该随机秘密，且拒绝网页 Origin 请求。页面加载或身份建立失败会保留可读错误，不降级为游客。

macOS 正常启动时，把正式 Agent 访问令牌保存到系统钥匙串，服务名是 `com.workloom.eagle.agent-access`，账户名是 `local-owner`。保存命令通过标准输入接收令牌，并立即回读核验；它不把令牌写入命令参数或明文文件。CLI/MCP 只在连接本机回环服务时读取这份钥匙串凭据。显式 `WORKLOOM_ACCESS_TOKEN` 仍优先。当前 Windows 接入需显式提供正式访问令牌，不能把本轮 macOS 实测当成 Windows 实测。

启动时生成支持目录下的 `agent-config/codex.toml`、`agent-config/mcp.json` 和 `agent-config/AGENT-INSTRUCTIONS.md`。其中只有准确可执行文件、产品路径、服务地址与流程约束，没有任何秘密。系统“模型与成本”页面会列出真实模型配置、凭据状态、Agent 会话是否就绪及这些文件的绝对路径。完整调用顺序见 [EAGLE-AGENT-GUIDE.md](EAGLE-AGENT-GUIDE.md)。

## 本机自包含验收构建

标准公开发行继续使用原有资产摘要、Bundle 签名、应用签名、公证与发布门禁。本机验收另外使用 `scripts/pack-eagle-local.mjs`，当前支持面明确为 macOS arm64。它从已安装的受控运行时中只读取 `node/`、`pg/`、`nats/`，复制到新的构建目录；不复制原应用的数据库、环境配置、日志或客户资料。

本机打包会构建真实生产 Web、按每产品精确运行依赖锁执行 `npm ci`，再对 staged 行业包运行原有发布签封契约。该签封使用只存在内存中的本机验收 Ed25519 私钥，公开信任环单独放在应用 Resources，私钥不随包、不落盘，也不修改仓库的行业包源资产。构建回执标记 `local-acceptance-ephemeral-ed25519` 及 `local-unsigned-not-notarized`，不能表述为官方签名、公证或公开发行通过。

本机打包示例：

```sh
node scripts/pack-eagle-local.mjs \
  --runtime-source '/path/to/existing/runtime-root' \
  --out '/path/to/isolated-build-directory'
```

构建回执 `local-client-receipt.json` 包含实际 source commit、是否存在未提交修改、载荷版本与 SHA-256、运行依赖清单摘要、三个二进制摘要和 Bundle 公钥环摘要。最终交付包必须在已提交源码上重建，并验证 `sourceDirty=false`。这份构建回执与启动后 `install-state.json`、`VERSION`、实际模型请求与业务产物回执共同构成验收证据，单有打包成功不能证明员工能力或业务交付通过。

归档前会使用载荷自身的 Node 和运行依赖实际启动 Web preview，并比对返回首页与本次构建的 `dist/index.html`。开发环境有测试依赖时构建成功，不能替代这项运行验证。生产 Vite 配置只引用正式依赖；Vitest 的单测配置位于独立的 `apps/web/vitest.config.ts`，不随正式载荷装配。配置拆分依据 [Vitest 官方配置说明](https://vitest.dev/config/)。

## 运行验证

无付费调用的正式认证负向验证：

```sh
node scripts/eagle-production-auth-smoke.mjs --base-url http://127.0.0.1:8897
```

该命令实查匿名 `loginAs`、游客、缺失安装凭据、错误安装凭据及网页 Origin 五个拒绝路径，不修改客户数据，也不触发模型。

数字员工真实模型能力、单员工任务、多员工任务拆解、断点恢复和最终产物必须使用独立评测预算与真实回执验证。完成状态只代表系统返回的具体业务结果；内部草稿仍需人类咨询师复核，不能写成最终诊断、人类访谈或对外发送已经完成。
